# Talos on the ThinkPad P53

This Terraform root bootstraps the single-node Talos cluster. Flux manages
infrastructure, application, and monitoring resources after bootstrap.
Cloudflare resources have been transferred from `k3s-server` to the
`mediafactory-talos` workspace.
Terraform Cloud uses the separate `mediafactory-talos` workspace so the
cluster migration does not share state with the former K3s setup.

Generate and download the ThinkPad image without applying the machine config:

```sh
tfale init
tfale apply -target=data.talos_image_factory_urls.thinkpad
curl -fL "$(tfale output -raw talos_disk_image)" -o talos-thinkpad.raw.zst
```

The raw disk image includes the configured extensions. Alternatively, use
`tfale output -raw talos_iso` to download the metal ISO. Boot the ThinkPad from
the chosen media into maintenance mode. For cluster bootstrap, create the
`mediafactory-talos` Terraform Cloud workspace, copy the required variable set
from `k3s-server` and set `master_server_list`. For this P53, `install_disk`
defaults to `/dev/nvme0n1`, and the selector also requires the Intel SSD serial
`PHHP943100NH512C`. Talos is configured to wipe that selected install disk.
Verify the live disk inventory before applying. `media_disk_uuids` contains
the three XFS UUIDs identified on the P53; `ExistingVolumeConfig` mounts those
filesystems without formatting them. Save the Talos kubeconfig locally after
bootstrap. Flux is enabled with the Kubernetes and Helm providers and syncs a
bootstrap path containing Longhorn, mergerfs, the NFS server, and the NFS CSI
driver. Metoro remains commented out and the Cloudflare provider remains
disabled. The normal `flux/clusters/home/` path with all apps stays inactive
until the Longhorn restore is complete. The
providers read `terraform/kubeconfig`; they cannot use credentials generated by
a Talos resource in the same apply. Run this workspace in local execution mode
so Terraform can read that ignored local file and run the Talos `local-exec`
provisioner.

```sh
cd terraform
tfale apply -target=talos_cluster_kubeconfig.this
umask 077
tfale output -raw kubeconfig > kubeconfig
tfale output -raw talosconfig > talosconfig
tfale apply
```

For operational Kubernetes and Flux commands, explicitly use
`KUBECONFIG=/Users/asottile/.kube/talos`. Terraform providers continue to
read their generated local `terraform/kubeconfig` file.

The local kubeconfig and talosconfig are ignored by Git. Keep other secrets in
Terraform Cloud or an ignored local `.tfvars` file.

Cloudflare resources are managed in this workspace and their state was moved
from `k3s-server` without deleting the live Cloudflare objects. Do not apply
the old `k3s-server` Terraform configuration: it still declares these
resources and would try to create them again after the state transfer.

The Flux `FluxInstance` syncs `master` at `flux/clusters/home/`; the
infrastructure and apps trees are active. Application and monitoring resources,
including Metoro, are managed declaratively by Flux rather than Terraform.

Talos installs onto the configured disk. The image includes
NVIDIA Turing drivers/toolkit, Intel iGPU
drivers, FUSE, NFS client/server kernel support, and the existing storage
extensions. The three existing XFS filesystems are selected by their current
UUIDs in `media_disk_uuids`; `ExistingVolumeConfig` only discovers and mounts
these filesystems. It does not partition or format them. Talos mounts them as
`/var/mnt/externaldisk1-3`; the mergerfs Pod combines them at `/run/mergerfs`
with the old branch-selection and cache options. This shared FUSE mountpoint
uses `/run` because Talos keeps `/var/mnt` read-only to Pods. The NVIDIA GPU Operator keeps
discovery, time-slicing, and metrics; Talos provides the driver and container
toolkit.

The former SSH provisioning of an NFS server has been removed because Talos
does not support installing host packages or managing systemd services. NFS
exports that used to come from the K3s host need a Kubernetes-hosted NFS server
or another existing NFS host.
